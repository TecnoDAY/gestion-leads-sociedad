Esquema SQL & Políticas RLS (Supabase)

Políticas de seguridad de fila, autenticación y sincronización en tiempo real

Para garantizar la integridad y seguridad en producción, ejecuta este script en el SQL Editor de tu Dashboard de Supabase: 

-- =======================================================
-- 1. CREACIÓN DE LA TABLA 'leads' (CON RESPETO A COLUMNAS)
-- =======================================================
CREATE TABLE IF NOT EXISTS public.leads (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    "Mes" TEXT,
    "Fecha" TEXT,
    "Nombre" TEXT NOT NULL,
    "Telefono" TEXT,
    "Campaña" TEXT,
    "Medio" TEXT,
    "GESTION" TEXT DEFAULT 'Información ',
    "Interesado en " TEXT,
    "Ciudad" TEXT,
    "AGENTE" TEXT,
    "Odoo" TEXT,
    "Fecha de Atencion" TEXT,
    "OBSERVACIONES " TEXT,
    "Fecha Última Gestión " TEXT,
    "ULTIMA GESTION" TEXT,
    "ULTIMO AGENTE " TEXT,
    "LANDING" TEXT,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- =======================================================
-- 2. HABILITACIÓN DE ROW LEVEL SECURITY (RLS)
-- =======================================================
ALTER TABLE public.leads ENABLE ROW LEVEL SECURITY;

-- =======================================================
-- 3. POLÍTICAS DE ACCESO ESTRICTAS (POLICIES)
-- =======================================================
-- La política segura se instala mediante la migración versionada.

-- Las inserciones y actualizaciones se ejecutan mediante RPCs estrechas.

-- No existe política directa de escritura para el navegador.

-- No existe política DELETE: el archivado se hace por RPC admin.

-- =======================================================
-- 4. HABILITACIÓN DE SINCRONIZACIÓN EN TIEMPO REAL
-- =======================================================
ALTER PUBLICATION supabase_realtime ADD TABLE public.leads;
